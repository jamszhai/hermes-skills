# 工程咨询合同起草

## 适用场景

用户要求起草或生成以下类型的文档：
- 设计咨询合同
- 工程勘察设计合同
- 城市更新项目咨询合同
- 基础资料调查/评估合同
- **工程设计费测算报告**（按收费标准计算各阶段设计费）
- **设计服务报价函/报价书**（以收费标准为依据向甲方报价）
- 其他以取费标准为依据的工程咨询类文档

## 标准流程

### 第一步：获取取费依据

1. 查找用户指定的取费标准文件（如《江苏省工程勘察设计收费导则2024版》）
2. 用 `search_files` 或 `read_file` 定位相关章节
3. 提取与用户需求匹配的收费单价/比例/计算公式
4. 确认费用包含的计费基数（如"更新总体方案费用"等）

### 第二步：确认合同要素

与用户确认以下关键信息（如用户未一次性提供，应先给出初稿再迭代）：

- **甲方/乙方** 全称
- **项目名称** 和 **项目地点**
- **工作范围**：具体调查/设计内容（如"用地及房屋权属情况调查与评估"）
- **合同金额**：用户指定具体金额，而非取费标准中的范围
- **付款方式**：分几次付款、各阶段比例、付款触发条件
- **工作期限**：首稿提交时间、修改确认流程
- **成果形式**：纸质版/电子版、份数
- **发票信息**：暂不填时留空即可

### 第三步：合同结构

标准设计咨询合同应包含以下条款：

```
1. 项目概况
2. 工作内容及成果要求
3. 合同金额及支付
4. 付款方式（逐条列明每次付款条件）
5. 双方权利义务
6. 工作期限
7. 知识产权与保密
8. 违约责任
9. 不可抗力
10. 争议解决
11. 其他约定
附件
双方签章
```

### 第四步：迭代修正

用户通常会提出以下修正，**初始版本应预先优化以减少迭代**：

- **工作范围收窄**：用户可能只取表3.2.3-1中的一项（如仅用地及房屋权属调查），而非全部
- **金额固定为具体数字**：取费标准给出的是比例范围（如10~20%），但用户会指定最终协商价，不要在合同中写比例，直接写金额
- **付款条件**：常见为 签后50% + 交付后50%，各7个日历天内
- **工作期限**：7个日历天首稿，修改不计入期限
- **成果形式**：用户可能指定"电子版一份"而非纸质
- **发票信息**：除非用户明确提供，否则留空
- **合同份数**：除非用户明确说明，否则留空（一式几份）

### 第五步：保存到 Obsidian

1. 确认用户 Obsidian 仓库路径（优先通过 `OBSIDIAN_VAULT_PATH` 环境变量；若未设置，用 `terminal` 寻找常见路径如 `F:/Obsidian Vault/LLM Wiki`）
2. 按照用户指定的文件夹名创建子目录，例如 `和润控股镇江文旅水街项目咨询合同`
3. 用 `write_file` 将合同 markdown 文件写入该目录
4. 同时保留一份在桌面方便用户取用

## 工程设计费测算流程

当用户要求计算设计费（初步设计/施工图设计/方案设计）时，按以下流程执行：

### 第一步：确定收费标准版本

区分用户引用的是哪个收费标准——两个版本的收费基价表数值不同：

| 标准版本 | 计费额10,000万元对应的收费基价 | 适用场景 |
|---------|:---------------------------:|---------|
| 2002年修订本（国家版） | 304.80 万元 | 国家计委、建设部联合发布 |
| 2024版（江苏省导则） | 381.00 万元 | 江苏省勘察设计行业协会发布 |

两者的**各阶段工作量比例**也不同：
- **2002版**：方案设计15%、初步设计30%、施工图设计55%
- **2024版**：方案设计25%、初步设计20%、施工图设计45%、后期服务10%

### 第二步：提取计费额

确认用户提供的计费基数：工程总造价（万元）。**不直接给的时候先问**。

### 第三步：直线内插法计算收费基价

收费基价表的数据是离散的，计费额落在两个数值之间时用直线内插法：

```
收费基价 = 基价低 + (基价高 - 基价低) × (计费额 - 额低) ÷ (额高 - 额低)
```

以2002版计费额13,000万元为例：
```
收费基价 = 304.80 + (566.80 - 304.80) × (13,000 - 10,000) ÷ (20,000 - 10,000)
         = 304.80 + 262.00 × 0.3 = 383.40 万元
```

完整的收费基价表见 `references/2002版工程设计收费基价表.md`。

### 第四步：应用调整系数

收费基价 × 专业调整系数 × 复杂程度调整系数 × 附加调整系数

| 调整系数 | 取值来源 | 典型值 |
|---------|---------|:----:|
| 专业调整系数 | 附表二（按工程类型） | 一般公共建筑=1.0 |
| 复杂程度调整系数 | 对应工程章节（Ⅰ/Ⅱ/Ⅲ级） | Ⅰ级0.85/Ⅱ级1.0/Ⅲ级1.15 |
| 改扩建附加调整系数 | 总则1.0.12 | 1.1~1.4（根据改造难度） |
| 附加调整系数合并规则 | 多个系数不能连乘，用公式：∑系数 - n + 1 |

### 第五步：按阶段拆分费用

基本设计收费已包含初步设计+施工图设计。单独委托某一阶段时：

```
初步设计费 = 基本设计收费 × 初步设计占比 ÷ (初步设计占比 + 施工图占比)
施工图设计费 = 基本设计收费 × 施工图占比 ÷ (初步设计占比 + 施工图占比)
```

以2002版（30%/55%）为例：
- 初步设计费 = 基本设计收费 × 30% ÷ 85% = 基本设计收费 × 35.3%
- 施工图设计费 = 基本设计收费 × 55% ÷ 85% = 基本设计收费 × 64.7%

### 第六步：浮动幅度

根据《收费管理规定》第六条，政府指导价浮动幅度为上下20%。最终合同价可在±20%范围内协商。

### 第七步：生成文档

- 测算报告：呈现完整的计算过程（基价→系数→基本设计收费→分阶段→浮动）
- 报价函：以报价函格式呈现，可直接对外发送

## 报价函（设计服务报价书）文档结构

当用户要求"报价函"或"报价书"时，使用以下文档结构，区别于合同：

```
1. 致函（项目名称、服务范围简述）
2. 项目概况（投资额、面积、层数、建设性质）
3. 收费依据（引用具体导则/标准条文号）
4. 报价方案
   A. 分项报价（逐项列明各设计阶段/技术服务费用）
   B. 打包暂估总价（可选，便于甲方快速决策）
5. 单位面积指标参考（折合元/㎡）
6. 商务条款（有效期、付款、不含费用、范围外计费）
7. 结语 + 签章栏
```

报价函中的费用应表明是"基准价"，注明"±20%浮动范围"，并提示"最终以合同约定为准"。

## Python-DOCX 文档生成规范

### 字体与样式

```python
from docx import Document
from docx.shared import Pt, RGBColor
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.enum.table import WD_TABLE_ALIGNMENT
from docx.oxml.ns import qn

doc = Document()
style = doc.styles['Normal']
style.font.name = '宋体'
style.font.size = Pt(10.5)
style.element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')
style.paragraph_format.line_spacing = 1.5
```

### 表格——蓝色表头

```python
def set_cell_shading(cell, color):
    tc = cell._tc
    tcPr = tc.get_or_add_tcPr()
    from docx.oxml import parse_xml
    shading = parse_xml(f'<w:shd {nsdecls("w")} w:fill="{color}"/>')
    tcPr.append(shading)

def format_table_header(table, rows=1):
    for i in range(rows):
        for cell in table.rows[i].cells:
            set_cell_shading(cell, "1A3C6E")  # 深蓝色背景
            for p in cell.paragraphs:
                p.alignment = WD_ALIGN_PARAGRAPH.CENTER
                for r in p.runs:
                    r.font.color.rgb = RGBColor(0xFF, 0xFF, 0xFF)  # 白色文字
                    r.bold = True
                    r.font.size = Pt(10)
```

### 标题样式

```python
# 深蓝色16进制 #1A3C6E
def add_heading_styled(doc, text, level=2):
    h = doc.add_heading(level=level)
    run = h.add_run(text)
    run.font.color.rgb = RGBColor(0x1A, 0x3C, 0x6E)
    run.font.name = '黑体'
    run.element.rPr.rFonts.set(qn('w:eastAsia'), '黑体')
    return h
```

### 核心结果高亮

关键费用数字用红色加粗（#CC0000）突出显示，单独占行。

### 表格数据

- 表格使用 `style='Light Grid Accent 1'` 或 `style='Medium Shading 1 Accent 1'`
- 表头行用 `format_table_header()` 设置为深蓝底白字
- 金额列和数据列分别清晰

## 注意事项

### 金额处理
- 合同金额必须同时写**阿拉伯数字**和**大写中文**
- 正确示例：**玖万元整（¥90,000.00）**
- 错误示例：仅写数字或仅写大写

### 付款条款
- 每次付款的金额必须同时写阿拉伯数字和大写
- 付款触发条件要明确，如"经甲方确认合格后"

### 中文表达
- 用户为中文母语者，合同全文使用简体中文
- 法律条款保持严谨正式，但避免过度冗长
- 甲方/乙方的全称在合同首部完整列出，正文中用"甲方""乙方"简称

### 留空项处理
- 用户未提供的信息用 `_________` 或 `____年____月____日` 占位
- 不主动猜测填写用户未提供的信息
- 发票信息、收款账户、法定代表人等除非用户明确给出，否则一律留空
