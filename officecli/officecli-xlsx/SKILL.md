# officecli-xlsx —— 保真编辑已有 Excel

## 何时用
- 用户给你一个**现有 xlsx**，要求"改面积/名称/单价""按这版改""在原来的基础上改""不要改颜色/格式"。
- 需要**修改而非从零新建** Excel，且成品要和原文件"长得一样、只变数据"。
- 典型场景：甲方造价估算表换楼栋面积与名称、删某些行、单价不变、据实重算合计。

## 核心原则：保真优先
重生成 Excel 时，**原文件的配色/字体/对齐/合并/列宽/行高必须原样复刻**。不要用自己觉得"好看"的新色、新字体、新布局。用户期望值 = 原版外观 + 新数据。

## 步骤
1. **读原文件，逐类提取样式**（见 `references/style_introspection.md`）：
   - 表头行 / 单价行 / 合计行 / 分区标题行的填充色 `cell.fill.fgColor.rgb`（openpyxl 返回 8 位 ARGB，如 `'FF44546A'`）。
   - 字体 `cell.font` 的 `bold / color.rgb / size / name`。
   - 对齐 `cell.alignment`（horizontal / vertical / wrap_text）。
   - `ws.merged_cells.ranges`、`ws.column_dimensions[col].width`、`ws.row_dimensions[r].height`。
2. **用变量固化原版颜色**（如 `NAVY='FF44546A'`、`YELLOW='FFFFF2CC'`），直接 echo 原文件读到的 rgb 字符串，不要自己另选色值。
3. **按原结构重建**：标题行 → 分区说明行 → 表头行 → 单价行 → 各数据行 → 合计行 → 第二部分 → 汇总行 → 注记。合并单元格、列宽、行高照原样设。
4. **只动数据，单价/公式逻辑保持原样、据实重算**：用户改了面积/名称/删行，就重算每行小计、改造合计、两项合计、综合造价；单价本身不动。
5. **另存为新文件**：原文件名加后缀（如 `_商办楼`），**绝不覆盖甲方原文件**。
6. **回读校验**（必须做）：重新打开成品，打印关键单元格的 value 与 fill，确认①颜色与原版一致②楼栋名称/面积正确③合计重算无误。

## 陷阱（踩过才写进来）
- ❌ **重生成时自己换配色**。本会话真实发生：把表头做成黄色、合计行不上色，用户明确回退"颜色按原来那版调，不要改"。原版的"表头深蓝灰+白字 / 单价黄行 / 合计浅橙 / 分区标题浅蓝灰"都是读出来复刻，不是凭记忆或审美重做。
- ❌ **覆盖原文件**。甲方原表要留底。
- ❌ **删/改行后不重算合计与汇总**。改造合计、两项合计、综合造价须据实重算；删掉低价行后"建筑单方"可能从 922 回到 930（分母变小），属正常，要在注记里说明口径变化。
- ❌ **数字格式不一致**。金额 `'#,##0'`、面积 `'#,##0.00'`、折合单方 `'#,##0.0'`，要和原版一致，否则显示位数对不上显得不专业。
- ❌ **自作主张加列/改表头文案**。除非用户要求，表头、单位、注记原文尽量保留。

## 与本会话其他偏好的衔接
- 生成完毕除了保存工作目录，顺手 **复制一份到桌面并改短文件名**，方便用户直接双击打开（用户曾反馈"放到哪去了，我打不开"）。
- 完成后回读验证关键内容再交付（与 officecli-docx 的"回读验证再交付"一致）。
